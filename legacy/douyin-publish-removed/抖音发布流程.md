## 三、日常使用

### 1. 发布单条视频（立即）
```bash
cd ~/social-auto-upload && source .venv/bin/activate
sau douyin upload-video --account main --file ~/视频自动搬运发布/熟肉视频/xxx_字幕.mp4 \
  --title "标题" --desc "简介" --tags "标签1,标签2"
```

### 2. 批量发布（CSV 方式，支持定时）
1. 复制 `videos.csv.example` 为 `videos.csv`，按列填：`video_path,title,desc,tags,schedule`（`schedule` 留空=立即发布，格式 `YYYY-MM-DD HH:MM`=定时）。
2. 执行：
```bash
~/social-auto-upload/.venv/bin/python \
  /Users/limingyu/视频自动搬运发布/批量发布/publish_douyin.py --csv videos.csv
```

### 3. 批量发布（自动扫描成品目录）
不传 `--csv` 时自动扫描 `~/视频自动搬运发布/熟肉视频/*.mp4`，以文件名作标题：
```bash
~/social-auto-upload/.venv/bin/python \
  /Users/limingyu/视频自动搬运发布/批量发布/publish_douyin.py --dry-run
```
`--dry-run` 只打印将执行的命令，不真正发布；确认无误后去掉该参数即可。

### 4. 完整链路（推荐）
VideoLingo 烧录完成 → 成品落到 `~/视频自动搬运发布/熟肉视频/` → 编辑 `videos.csv` 填标题/话题/定时时间 → 跑批量脚本 → 发布完成（可配合 `launchd`/`cron` 定时自动执行，实现全自动矩阵发布）。

## 四、账号与登录

- 当前账号名：`main`（对应 `cookies/douyin_main.json`）。
- 登录方式（Cookie 过期后重新执行）：
  1. 用 launchd 托管启动带调试端口的 Chrome（独立配置，不影响日常浏览器）：
     ```bash
     launchctl submit -l com.douyin.debug-chrome -- "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
       --remote-debugging-port=9222 --remote-allow-origins="*" \
       --user-data-dir=/tmp/douyin-debug-profile-20260805 --no-first-run --no-default-browser-check \
       "https://creator.douyin.com/"
     ```
  2. 在窗口里扫码登录，保持标签页打开。
  3. 导出 Cookie：
     ```bash
     cd ~/social-auto-upload && export PATH="$PWD/.venv/bin:$PATH" && bash export_douyin_cookie.sh --account main
     ```
  4. 校验：`sau douyin check --account main`，输出 `valid` 即成功。
  5. 用完关闭调试浏览器：`launchctl remove com.douyin.debug-chrome`。
- 若发布时触发短信二次验证：程序会读取仓库根目录 `verify_code.txt`（写入验证码即可），交互终端下也可直接输入。

## 五、注意事项 / 排障

| 场景 | 做法 |
|---|---|
| Cookie 失效（check 非 valid） | 按第四节重新导出 |
| 想要批量矩阵多账号 | 再登录一个账号名（如 `main2`），脚本 `--account main2` |
| 发布频率控制 | 建议每账号每天 ≤ 2-3 条，用 `schedule` 分散到不同时段，降低风控风险 |
| 视频要求 | 建议 9:16 竖版 1080×1920；≤ 15 分钟、≤ 4GB；横版也可发但推荐竖版 |
| 标题/话题 | 抖音标题上限约 55 字；话题直接写 `#话题` 或 `--tags`，避免蹭无关热点 |
| 升级项目 | `cd ~/social-auto-upload && git pull && source .venv/bin/activate && uv pip install -e .`，必要时 `patchright install chromium` |
| 代理 | GitHub 拉取/升级需 Clash `127.0.0.1:7897`；抖音发布走直连即可 |

## 八、竖屏视频清晰度问题（已修复）

**结论：是下载设置的问题，不是 YouTube 原视频模糊。**

原因：下载格式固定为 `bestvideo[height<=1080]`，按“高度”过滤。竖屏视频（如 1080×1920）高度=1920 直接被排除，yt-dlp 只能退而求其次下载 **608×1080** 的低清版本（实测两条例证均被下载成 608×1080）。

修复：下载前先探测视频方向——
- 横屏视频：仍按 `height<=1080`（1920×1080 正确）；
- 竖屏视频：改按 `width<=1080`（可正确命中 1080×1920）；
- 配置项 `ytb_resolution` 语义变为“最长边不超过 1080”。

**已验证（2026-08-05，视频 ElsnleFR1YE）**：`yt-dlp -F` 确认 YouTube 提供 1080×1920 三档格式（avc1 2809k / vp9 1171k / av01 933k），旧代码只能拿到 608×1080（yt-dlp 标称 480p，555k）。用修复后代码重新下载实测结果：

| 项 | 旧代码 | 新代码 |
|---|---|---|
| 分辨率 | 608×1080 | **1080×1920** |
| 码率 | ~551k | ~933k（av01，三档中 yt-dlp 默认最优档） |
| 体积 | 5.1MB | 7.8MB |

如需更高码率可把网页分辨率切换为「Best」（会取 avc1 2809k 档，文件约 20MB）。
