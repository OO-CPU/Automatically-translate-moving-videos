# FreshRSS 私人新闻阅读器需求

最后更新：2026-09-04

## 1. 项目背景

在现有 VPS 上部署一套轻量、私有的新闻阅读服务，集中收集用户关注的科技、羽毛球、经济与股票市场资讯。

服务器负责从境外及境内 RSS/Atom 源抓取文章、标题、摘要和图片。用户通过自己的域名访问 FreshRSS 网站，在电脑或手机上阅读。阅读服务器已经抓取的内容时，原则上不依赖本地代理；点击受限网站的原文链接时，仍可能需要本地代理。

## 2. 建设目标

1. 提供一个通过 HTTPS 访问的私人新闻网站。
2. 集中订阅科技、羽毛球、经济与股票市场信息。
3. 支持文章分类、搜索、收藏、未读状态和跨设备同步。
4. 由 VPS 代理并缓存文章图片，改善国内网络下的阅读体验。
5. 控制信息数量，减少重复报道、低质量内容和过期快讯。
6. 运行轻量，不明显影响 VPS 上已有代理、Nginx、备份和 YouTube 监控服务。
7. 配置和订阅数据可备份、恢复和迁移。

## 3. 非目标

本项目不包含以下功能：

- 不提供实时股票行情、交易或投资建议。
- 不作为访问任意境外网站的通用代理。
- 不自动绕过付费墙、登录验证或网站访问限制。
- 不永久保存所有新闻图片和网页副本。
- 第一阶段不部署 RSSHub、全文爬虫、LLM 自动摘要或推荐算法。
- 不开放 FreshRSS 容器的独立公网端口。

## 4. 服务器约束

当前 VPS 资源与环境：

- 1 核 CPU。
- 约 1 GB 内存。
- 无 GPU。
- 系统盘约 20 GB，目前约 17 GB 可用。
- 已运行 Nginx、Docker、代理服务、Fail2ban、备份任务和 YouTube 邮件监控。
- 公网入口继续仅使用现有 HTTP/HTTPS 端口，不新增入站端口。

因此应使用 FreshRSS 的轻量部署方式，采用 SQLite，不引入独立 MySQL/PostgreSQL 服务。

## 5. 总体架构

```text
RSS / Atom / YouTube 频道 / 新闻关键词源
                    ↓
          FreshRSS 定时抓取与去重
                    ↓
       SQLite + 本地有限容量图片缓存
                    ↓
             Nginx HTTPS 反向代理
                    ↓
          https://rss.<用户域名>
                    ↓
         浏览器或兼容 RSS 客户端阅读
```

推荐部署结构：

- FreshRSS 使用官方稳定版 Alpine 容器。
- 数据库使用 SQLite。
- FreshRSS 仅监听 `127.0.0.1` 或 Docker 私有网络。
- 由现有 Nginx 提供 HTTPS 入口。
- 使用独立子域名，建议为 `rss.<用户域名>`。
- 域名、证书路径和最终用户名在部署前确认。

## 7. 抓取与阅读规则

### 7.1 抓取频率

- FreshRSS 每 2 小时静默抓取一次，避免因源站只保留少量最新项目而漏掉文章。
- 用户主要在每天早晨阅读“过去 24 小时”的内容。
- 抓取过程不主动发送通知，除非后续明确增加每日摘要功能。
- 单个订阅抓取失败不得阻塞其他订阅。

### 7.2 分类

至少建立以下分类：

- `科技`
- `羽毛球`
- `经济与市场`
- `视频选题`（为未来添加更多 YouTube 频道预留）

### 7.3 信息控制

- 使用 FreshRSS 自身的文章唯一标识和链接进行去重。
- 高频科技快讯超过 48 小时后可自动标记已读或清理。
- 羽毛球、经济与市场资讯默认保留 30 天。
- 用户收藏的文章长期保留。
- 第一版订阅源总量控制在约 15 个以内。
- 部署后根据一至两周的实际阅读体验删除低质量、高重复来源。
- 不自动合并内容不同但标题相似的文章，避免误删重要信息。

## 8. 图片代理与缓存

### 8.1 目标

FreshRSS 页面中的文章配图、封面图和 YouTube 缩略图应尽可能由 VPS 代为抓取并通过同一域名提供，减少用户浏览器直接连接境外图片域名的情况。

推荐使用 FreshRSS 官方 Image Proxy 扩展，配合受限的图片代理和 Nginx 缓存。

### 8.2 缓存策略

- 图片缓存容量上限：初始 512 MB，可根据磁盘情况调整，最大不超过 1 GB。
- 7 天未被访问的缓存自动清理。
- 单张图片大小上限：10 MB。
- 仅允许常见图片 MIME 类型。
- 对缓存目录设置独立容量和日志限制。
- 图片缓存不进入长期异地备份，可随时重新生成。

### 8.3 安全要求

- 图片代理不得成为公开的任意 URL 转发服务。
- 阻止访问 loopback、私有网段、链路本地地址和云主机元数据地址。
- 防止通过重定向绕过内网地址限制。
- 设置请求速率限制、连接超时、响应体上限和缓存键校验。
- 图片代理入口仅供 FreshRSS 页面使用。

### 8.4 已知限制

- RSS 内容本身没有图片时，图片代理无法生成图片。
- JavaScript 动态加载、必须登录、带短期签名或严格防盗链的图片可能无法缓存。
- 点击原文后，原站图片和网页是否可访问仍取决于用户本地网络。

## 9. 用户访问与同步

### 9.1 网页访问

- 用户通过 `https://rss.<用户域名>` 登录。
- 页面应支持电脑和手机浏览器。
- 未登录用户不得查看订阅内容。

### 9.2 手机与桌面客户端

- 启用 FreshRSS Google Reader 兼容 API。
- 每个用户设置独立 API 密码，不复用网页主密码。
- API 地址预计为：`https://rss.<用户域名>/api/greader.php`。
- 可使用 Reeder Classic、Fluent Reader Lite、lire 等兼容客户端。

### 9.3 无域名应急访问

域名或证书故障时，可通过 SSH 本地端口转发临时访问，不将容器端口直接开放到公网。

## 10. 账户与安全

- 采用单用户模式。
- 关闭公开注册。
- 使用高强度登录密码。
- 管理员密码和 API 密码不得写入 Git 仓库。
- 敏感配置只保存在服务器受限权限文件和本机已忽略的 `.private/` 目录。
- 强制 HTTPS，不允许通过明文 HTTP 登录。
- Nginx 设置合理的安全响应头、请求大小限制和速率限制。
- 保留 FreshRSS 默认 SSRF 防护，不允许通配放开内部地址访问。
- 容器以非 root 身份运行，并设置 CPU、内存及日志上限。
- 不使用自动更新所有容器的 Watchtower；升级前先备份并进行人工验证。

## 11. 备份与恢复

需要备份：

- FreshRSS SQLite 数据库。
- 用户配置、分类、订阅和收藏状态。
- FreshRSS 扩展配置。
- Nginx 站点配置和容器编排文件。

不需要备份：

- 图片缓存。
- 临时文件。
- 可重新拉取的容器镜像。

备份应纳入 VPS 现有加密备份流程，并至少进行一次恢复验证。部署和升级前均应生成可回滚备份。

## 12. 运行维护

- 提供容器健康检查。
- 限制日志文件大小并启用轮转。
- 监控磁盘占用、FreshRSS 抓取失败和证书有效期。
- FreshRSS 或图片代理异常不得影响 VPS 上的代理服务和 YouTube 监控。
- 更新使用固定版本号，先检查发布说明，再备份和升级。
- 发生连续抓取失败时记录日志；是否发送邮件告警由后续决定。

## 13. 验收标准

部署完成后应满足：

1. 通过指定 HTTPS 子域名正常打开 FreshRSS。
2. 未登录用户无法查看订阅内容。
3. 科技、羽毛球、经济与市场三个分类均有可正常刷新的订阅。
4. 候选 RSS 源能成功抓取，中文和英文标题显示正常。
5. 每 2 小时自动刷新，无需用户保持浏览器在线。
6. 文章图片优先通过本站图片代理加载，常见新闻配图可正常显示。
7. 图片缓存不会无限增长，容量和过期规则生效。
8. 手机浏览器阅读正常。
9. Google Reader API 配置检查通过，兼容客户端可以同步未读和收藏状态。
10. FreshRSS 重启后订阅、阅读状态和收藏不丢失。
11. VPS 内存、磁盘和现有服务运行状态无明显异常。
12. 备份包含数据库和配置，并具备明确的恢复步骤。

## 14. 待确认事项

正式部署前需确认：

- 用户域名及用于 FreshRSS 的子域名。
- DNS 托管平台以及是否可以添加或修改 DNS 记录。
- HTTPS 证书采用现有证书还是单独申请 Let's Encrypt 证书。
- FreshRSS 登录用户名。
- 是否需要每日邮件摘要；默认不启用。
- 是否需要增加其他 YouTube 羽毛球频道。
- 是否需要导入现有 OPML 订阅文件。

## 15. 后续可选增强

以下功能不纳入第一阶段，运行稳定后再评估：

- 每日早间邮件摘要。
- 关键词命中通知。
- 更多 YouTube 视频选题频道。
- 对少量摘要型 RSS 获取全文。
- LLM 自动分类或摘要。
- 与本地视频任务队列联动，将收藏的视频条目加入 Mac 处理队列。
